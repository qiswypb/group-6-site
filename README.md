# GLAM.exe – Y2K Fashion Store

## Project Overview

GLAM.exe is a Y2K-inspired online fashion store that showcases trendy clothing and accessories influenced by the early 2000s fashion era. The website aims to provide users with an interactive and visually appealing shopping experience by featuring different fashion styles, product categories and information about the store. It is developed using HTML and CSS to create a simple, user-friendly platform that reflects the unique and nostalgic aesthetic of Y2K fashion.

## Technologies Used

- **HTML5** – Used to structure the webpages.
- **CSS3** – Used to style and enhance the visual appearance of the website.
- **Git** – Used to track changes and manage project files.
- **GitHub** – Used to store the project online, collaborate with teammates and review changes through Pull Requests.
- **Laravel Herd** – Used to run the website locally with a secure HTTPS link.

## How to Run the Website

1. Clone the repository:

   ```bash
   git clone https://github.com/qiswypb/group-6-site.git
   ```

2. Open the project folder:

   ```bash
   cd group-6-site
   ```

3. Link the project using Laravel Herd:

   ```bash
   herd link
   ```

4. Secure the local website:

   ```bash
   herd secure group-6-site
   ```

5. Open the website using:

   `https://group-6-site.test`

## Git Collaboration Workflow

Our group used Git and GitHub to collaborate and manage the development of the website.

1. Each member created a separate feature branch for their assigned tasks.
2. Members made changes and updates to their respective webpages.
3. Changes were saved using Git commits.
4. Each member pushed their branches to GitHub.
5. Pull Requests were created to propose changes to the main branch.
6. Group members reviewed the changes before approving and merging the Pull Requests.

## Merge Conflict Resolution

During the project, our group encountered merge conflicts in `README.md` and `style.css` while combining changes from different branches.

We compared the conflicting changes, identified the differences and kept the necessary content and styling before completing the merge. This process helped us understand how Git handles conflicting changes and the importance of reviewing code carefully when collaborating with others.
